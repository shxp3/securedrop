## 5.2 แผนพัฒนาโครงการ (Development Roadmap)

โครงการแบ่งเป็น **6 เฟส** ระยะเวลารวมประมาณ **8-10 สัปดาห์** เหมาะกับกรอบเวลาการแข่งขัน STEAM ทั่วไป

```
สัปดาห์ 1-2   │ PHASE 1: วิจัยและออกแบบ (Research & Design)
              │  - ศึกษา datasheet ของทุกอุปกรณ์
              │  - ออกแบบสถาปัตยกรรมระบบ + wiring diagram (เอกสารชุดนี้)
              │  - ตั้งค่า Firebase project + Telegram Bot
──────────────┼────────────────────────────────────────────────
สัปดาห์ 3     │ PHASE 2: Proof of Concept แต่ละโมดูลแยกกัน
              │  - ทดสอบ GM65 อ่านบาร์โค้ดได้
              │  - ทดสอบ Solenoid + Relay ปลด/ล็อกได้
              │  - ทดสอบ HC-SR04, MPU6050, SW-420 อ่านค่าได้ถูกต้อง
              │  - ทดสอบ ESP32-CAM ถ่ายภาพ + อัปโหลด Firebase Storage
──────────────┼────────────────────────────────────────────────
สัปดาห์ 4-5   │ PHASE 3: บูรณาการซอฟต์แวร์ (Software Integration)
              │  - พัฒนา State Machine หลักใน main_controller
              │  - เชื่อมต่อ Firebase CRUD (database.cpp)
              │  - เชื่อมต่อ Telegram Bot (notification.cpp)
              │  - ทดสอบ Communication Protocol ระหว่าง 3 บอร์ด
──────────────┼────────────────────────────────────────────────
สัปดาห์ 6     │ PHASE 4: ประกอบฮาร์ดแวร์จริง (Hardware Assembly)
              │  - ประกอบวงจรลงกล่องจริง
              │  - เดินสายไฟ + ทดสอบ Power Budget
              │  - ติดตั้ง UV-C พร้อม Safety Interlock ทางฮาร์ดแวร์
──────────────┼────────────────────────────────────────────────
สัปดาห์ 7     │ PHASE 5: ทดสอบระบบทั้งหมด (System Testing)
              │  - ทดสอบ End-to-End Flow ตาม Test Plan (ดูเอกสาร 06)
              │  - ทดสอบ Edge Cases (บาร์โค้ดผิด, ประตูเปิดค้าง, จำลองขโมย)
              │  - ปรับจูน threshold ของเซนเซอร์จากการทดสอบจริง
──────────────┼────────────────────────────────────────────────
สัปดาห์ 8     │ PHASE 6: จัดทำเอกสารและเตรียมนำเสนอ
              │  - จัดทำ Poster/Slide/วิดีโอสาธิต
              │  - ซ้อมตอบคำถามกรรมการ (ดูสคริปต์สาธิตในเอกสาร 06)
              │  - เตรียมกล่องสำรอง/แผน backup กรณีอุปกรณ์ขัดข้องหน้างาน
──────────────┼────────────────────────────────────────────────
(สำรอง)       │ PHASE 7 (Buffer): แก้ไขปัญหาเฉพาะหน้า
สัปดาห์ 9-10  │  - เผื่อเวลาสำหรับปัญหาที่ไม่คาดคิด (Hardware DOA, บั๊กซอฟต์แวร์)
```

## 5.3 Milestone และเกณฑ์ความสำเร็จ (Definition of Done ต่อเฟส)

| Milestone | เกณฑ์ผ่าน |
|---|---|
| M1: Barcode → Unlock | สแกนบาร์โค้ดที่ลงทะเบียนแล้ว ต้องปลดล็อกได้ภายใน < 2 วินาที |
| M2: Parcel Detection → UV | วางพัสดุจริง + ปิดประตู ต้องเข้าสู่ UV cycle ได้ถูกต้อง 100% ในการทดสอบ 20 ครั้ง |
| M3: Camera Evidence | ภาพคนส่งและภาพพัสดุต้องอัปโหลดสำเร็จและดูได้ผ่าน Firebase Console |
| M4: Notification | ข้อความ Telegram ต้องมาถึงภายใน < 5 วินาทีหลังเหตุการณ์ พร้อมรูปครบ |
| M5: Anti-Theft | จำลองการยก/เขย่ากล่อง ต้องมี alarm ภายใน < 1 วินาที และ False Alarm Rate < 5% จากการทดสอบ 50 ครั้งในสภาวะปกติ |
| M6: Safety Interlock | ทดสอบเปิดประตูขณะ UV กำลังทำงาน ต้องดับทันที (< 200ms) ทุกครั้งโดยไม่มีข้อยกเว้น |
