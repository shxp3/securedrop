# 6. แผนทดสอบระบบ และสคริปต์สาธิตหน้ากรรมการ

## 6.1 Test Plan (สรุปเคสทดสอบสำคัญ)

| ID | Test Case | ขั้นตอน | ผลที่คาดหวัง |
|---|---|---|---|
| TC-01 | สแกนบาร์โค้ดที่ถูกต้องและยังไม่ใช้ | สแกน tracking number ที่ลงทะเบียนไว้ | Solenoid ปลดล็อกภายใน 2 วิ, LED เขียวติด |
| TC-02 | สแกนบาร์โค้ดที่ไม่มีในระบบ | สแกน tracking number สุ่ม | ระบบปฏิเสธ, LED แดงกระพริบ, ไม่ปลดล็อก |
| TC-03 | สแกนบาร์โค้ดที่ใช้ไปแล้ว | สแกนซ้ำ tracking number ที่ status="delivered" | ระบบปฏิเสธพร้อมข้อความ "Already Used" |
| TC-04 | วางพัสดุแล้วปิดประตู | หลังปลดล็อก วางกล่องของจริงแล้วปิดประตู | HC-SR04 ตรวจพบ, ล็อกอัตโนมัติ, เข้า UV cycle |
| TC-05 | ไม่วางพัสดุ ปิดประตูเปล่า | ปลดล็อกแล้วปิดประตูโดยไม่วางอะไร | Timeout, ไม่เข้า UV, แจ้งเตือน "ไม่พบพัสดุ" |
| TC-06 | เปิดประตูขณะ UV ทำงาน (Safety Test) | ระหว่าง UV active ให้เปิดประตู | UV ต้องดับทันที < 200ms |
| TC-07 | จำลองการยกกล่อง | ยกกล่องขึ้นเบา ๆ ระหว่าง state ARMED | Alarm ทำงานทันที, ถ่ายภาพ, ส่ง Telegram alert |
| TC-08 | จำลองแรงสั่นสะเทือนเบา (ลมพัด/รถผ่าน) | เคาะเบา ๆ ที่พื้นข้างกล่อง (ไม่ใช่ตัวกล่องโดยตรง) | ไม่ควร trigger alarm (ทดสอบ false positive) |
| TC-09 | WiFi หลุดระหว่างทำงาน | ปิด router ชั่วคราวระหว่าง flow | ระบบ cache ข้อมูล ไม่ค้าง, reconnect อัตโนมัติแล้ว sync ย้อนหลัง |
| TC-10 | Telegram Command /ack | ยิง /ack ผ่านบอทหลัง alarm | Alarm ต้องหยุด, บันทึก acknowledged=true ใน Firebase |

## 6.2 สคริปต์สาธิตหน้ากรรมการ (Demo Script ~5-7 นาที)

1. **เปิดตัว (30 วิ):** อธิบายปัญหา "พัสดุถูกขโมยหน้าบ้าน" และแนะนำ SecureDrop พร้อมโชว์ตัวกล่องจริง
2. **สาธิต Flow ปกติ (2 นาที):**
   - สแกนบาร์โค้ดที่ลงทะเบียนไว้แล้ว → โชว์กล่องปลดล็อก
   - เปิดกล่อง วางพัสดุจำลอง ปิดฝา
   - โชว์หน้าจอ Firebase/Telegram แสดงภาพคนส่ง + ภาพพัสดุ + ข้อความแจ้งเตือนแบบ real-time
   - อธิบายสั้น ๆ ว่ากำลังฉาย UV-C อยู่ (โชว้นับถอยหลังผ่าน OLED ถ้ามี)
3. **สาธิตระบบปฏิเสธ (1 นาที):** สแกนบาร์โค้ดปลอม/ที่ใช้ไปแล้ว → โชว้ว่าไม่ปลดล็อก
4. **สาธิตระบบกันขโมย (1-2 นาที):** จำลองยก/เขย่ากล่อง → โชว้ไซเรนดัง + Telegram alert แบบ real-time พร้อมภาพ
5. **สาธิต Safety Interlock (30 วิ):** เปิดฝาระหว่าง UV ทำงาน → โชว้ว่า UV ดับทันที (เน้นจุดนี้เพราะกรรมการมักถามเรื่องความปลอดภัย)
6. **สรุปปิดท้าย (30 วิ):** พูดถึงต้นทุน, ความเป็นไปได้ทางการตลาด, และแนวทางพัฒนาต่อ

## 6.3 คำถามที่กรรมการมักถาม และแนวทางตอบ

| คำถาม | แนวทางตอบ |
|---|---|
| ถ้า WiFi ไม่มีสัญญาณจะทำอย่างไร | อธิบายกลไก cache-and-retry + เสนอ RFID/PIN สำรองสำหรับเปิดฉุกเฉิน (future improvement) |
| UV-C ปลอดภัยกับพัสดุ/ผู้ใช้แน่หรือ | อธิบาย Hardware Interlock ที่ผูกกับ door sensor ทางวงจรจริง ไม่ใช่แค่ซอฟต์แวร์ |
| ทำไมต้องใช้ ESP32 3 ตัว ไม่ใช้ตัวเดียว | อธิบายข้อจำกัดขา GPIO ของ ESP32-CAM และหลักการ Separation of Concerns |
| ถ้ามีคนขโมยบาร์โค้ดจริงไปสแกนแทน | อธิบาย future improvement เรื่อง 2FA/OTP ยืนยันตัวตนคนส่งเพิ่มเติม |
| ระบบนี้ต่างจากตู้ล็อกเกอร์ไปรษณีย์ทั่วไปอย่างไร | เน้นจุดขาย: ยืนยันบาร์โค้ดเฉพาะเจ้าของ + ฆ่าเชื้อ UV-C + กันขโมยแบบ real-time ในกล่องเดียว ราคาประหยัด |
